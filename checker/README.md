# checker：de-ai-slop 機械檢查

把 de-ai-slop 規則裡「用字串或簡單句型就能判定」的部分做成本機檢查，交稿前先跑一次。只列出命中、不改文字；其餘規則仍要照 `SKILL.md` 第七節逐條對照。

需要 Node 22 以上，沒有第三方套件。

```bash
node checker/check.mjs 草稿.md                    # 長文（預設 --type article）
node checker/check.mjs 貼文.html --type post       # FB 等社群貼文（HTML 或純文字）
node checker/check.mjs - --type threads < 主文.txt # Threads 主文，從標準輸入讀
node checker/check.mjs 說明.txt --type notice      # 寫給非技術讀者的說明（回饋單、給客戶的信）
node checker/check.mjs 草稿.md --json              # 給程式讀
node checker/check.mjs --help
```

- 每個命中列出規則編號、等級（錯誤／提醒）、行號、原文片段、建議。HTML 輸入的行號是轉成文字後的行號（段落之間空一行、`<br>` 換一行）。
- 退出碼：0 沒有命中、1 有命中、2 用法錯誤（含檔案讀不到）。`--errors-only` 只列錯誤。
- 程式區塊、行內程式碼、網址、連結目標、HTML 標籤不檢查詞語。
- 測試：`node --test checker/check.test.mjs`

## 私有名詞清單（不放進 repo）

老師、站名、客戶這類名稱不能寫進對外文字（R9），但清單本身也不能公開，所以程式只從外部檔讀：

- `--private-terms <路徑>`（可重複）
- 環境變數 `DEAI_SLOP_PRIVATE_TERMS`（冒號分隔多個路徑）
- `~/.config/de-ai-slop/private-terms.txt`（存在的話）

檔案格式：一行一個詞，`#` 開頭是註解，`re:` 開頭當正規表示式。也可以直接指定自己的敏感字掃描 `.sh` 腳本，程式會讀出裡面 `grep -e '...'` 的樣式。沒設定任何清單時，文字輸出最後會提醒「未檢查老師、站名、客戶名稱」。

## 作者文風卡的詞（`--style-card`）

作者個人文風卡另外列了一批不用的詞（「丟進來」「送 PDF」「這陣子」「差很多」等）。這些是個人用詞偏好、不是通用規則，預設不檢查，加 `--style-card` 才檢查，規則編號顯示 `SC`。

## 可以機械判定的規則（本程式有做）

等級：錯誤＝規則明文禁止、命中幾乎都要改；提醒＝規則有例外或要看上下文，命中後由人判斷。

| 編號 | 規則原文（節錄一句） | 程式怎麼判定 | 等級 |

| R12 | 「不用『不是 X，是 Y』對比句，所有變體都算……交付前全文搜『而是』『不是』」 | 「而是」；同一句裡「不是…，是…」；「不只／不僅…更」 | 錯誤（「不只…更」為提醒） |
| R14 | 「不自己造『你以為 X，（等）Y 才發現 Z』句型」 | 「你以為…才發現／結果發現」；「做完才發現」 | 錯誤／提醒 |
| R15 | 「『先說結論』『一句話總結』『事實是』『老實說？』『更有意思的是』、開場自我介紹『哈囉，我是…』、『你是否也曾…』都不用」 | 規則列的詞 | 錯誤 |
| R16 | 「不用『首先→其次→接著→最後→總的來說』串段落」 | 首先、其次、總的來說、總而言之；ai-tells 表另列的「此外」 | 錯誤（此外為提醒） |

| R11 | 「刪掉『這是最在意的賣點』『我們也真的做到了』『這比…更有說服力』『可以寫一句誠實的話』」 | 規則列的詞；bad-examples 第 47 條的寫稿提醒（「（需說明」「（另註明」「誠實標明」） | 錯誤 |
| R10 | 「不特地列一段『還不知道的事』『沒有結論的部分』」 | 這兩個詞 | 錯誤 |
| R6 | 「不要改寫成『目前僅支援某平台』」 | 目前僅支援 | 提醒 |
| R20 | 「動詞取代名詞化。『進行評估』寫『評估』」 | 「進行」＋常見動詞（評估、分析、處理、測試…），「進行中」除外 | 提醒 |

| R65（bad-examples 49） | 「不要問有沒有錯誤 而是問學生平常都怎麼用」 | 「有遇過…嗎」 | 提醒 |

| R55、R68 | 「全文也搜一次，同一件事在兩處各講一遍就刪掉一處」 | 只做最機械的一種：15 個中文字以上、完全相同的句子出現兩次 | 提醒 |

## 只能人判斷的規則（本程式不做）

| 編號 | 規則原文（節錄一句） | 為什麼不做 |
|---|---|---|
| R1、R2、R4、R7 | 「每個具體宣稱都要有出處」「不編情境、案例、數字」 | 要對照素材與紀錄，程式看不到出處 |
| R3「最近」 | 「也不用『最近』『某位朋友』湊」 | 素材裡真的有時間時「最近」是對的；作者本人的貼文也用，誤報高 |
| R5、R27 | 「說明功能或流程用真實截圖」「圖片已經呈現的內容，文字不重複寫」 | 要看圖 |
| R8、R10 判斷部分、R21、R23、R25、R26、R28、R29 | 「內容要跟產品現況一致」「技術細節不寫」「限制要附出路」 | 要懂產品現況與讀者 |
| R13 | 「三段排比、『誰…、什麼…、到哪…』、『從 X 到 Y』都刪」 | 試做「從 X 到 Y」：近期 8 篇文章 13 個命中幾乎都是實際的範圍或數字變化（「從 0.111 美元降到 0.094 美元」），誤報太多，拿掉 |
| R19「對齊」 | 「『護城河』『對齊』……」 | 技術文常寫「置中對齊」「欄位對齊」，誤報高 |
| R30、R48、R55 一般情況 | 「讀者拿掉這句也不會少知道什麼，就刪」 | 換句話說的重複、可想而知的句子要讀懂才判斷 |
| R31～R35、R60、R62、R63 | 「章節標題用讀者心中的問題命名」「小標題簡短」 | 規則沒有字數門檻，要看標題跟內容合不合 |
| R39 條列 | 「貼文的條列歸零」 | 跟作者文風卡衝突：作者本人的貼文用「1、」與「・」條列 |
| R40 | 「長短句交替，允許不完整」 | 沒有門檻，句長變異量不等於讀起來順 |
| R42、R54 | 「不用翻譯腔」 | 要讀懂句構 |
| R43 | 「個人帳號不用『我們』」 | 跟作者文風卡衝突：「我」和「我們」作者都用（跟夥伴一起做時） |
| R47、R46 一般情況、R49、R51、R52 | 「白話詞第一次出現時，括號加註讀者搜得到的原名」 | 要知道哪些詞讀者不懂、是不是同物異名 |
| R50、R58、R59 一般情況、R61 | 「問句標題下的第一句，用跟人對話的口吻直接回答」 | 要讀懂回答了沒 |
| R64 | 「（待驗證的觀察，目前不是寫作禁令）」 | 規則本身說不拿來強制改寫 |
| R65 跨頁 | 「同一句 CTA 或說明文字，全站不在 3 處以上逐字重複」 | 要掃全站，單一檔案看不到 |
| R67 | 「判斷用邏輯，不背詞彙清單」 | 規則本身禁止用詞彙清單判斷 |
| R69 | 「主語和主要動詞不要隔太遠」 | 要斷詞與句法分析 |
| R70 | 「舉具體事例前，先確認第一次來的讀者有足夠的上下文看懂它」 | 要知道讀者背景 |
| R71 一般情況 | 「只講畫面上發生的事」 | 要對照畫面 |
| R72 | 「開頭先講讀者能得到什麼，再交代這是誰做的、為什麼做，帶數字的結果放後面」 | 開頭順序與「太擠」要讀懂；規則也明說「不訂數字上限，看讀起來順不順」 |
| ai-tells「中 3 條以上整段重寫」 | 「真人認 AI 文用的是集群判斷」 | 多數破綻（句長均勻、情感扁平、沒有錨點）不能機械判定，程式的命中數不等於破綻數 |
